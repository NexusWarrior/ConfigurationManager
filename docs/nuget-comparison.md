# Сравнение со штатным инструментом NuGet

Для контрольного сравнения используется команда .NET 10:

```shell
dotnet package list --project Sample.csproj --include-transitive
```

Для .NET 9 и более ранних версий порядок слов обратный:

```shell
dotnet list Sample.csproj package --include-transitive
```

## Совпадения

- Оба инструмента показывают прямые и транзитивные зависимости.
- Для пакетов без зависимостей оба результата содержат только корневой пакет.
- Циклические ссылки не приводят к бесконечному обходу в приложении.

## Ожидаемые расхождения

Штатная команда работает с проектом, выполняет восстановление пакетов и выводит
версии, разрешённые для конкретной целевой платформы. NuGet применяет правила
минимальной подходящей версии, приоритета прямой зависимости и разрешения
конфликтов между соседними ветвями.

Разработанный инструмент работает с пакетом, а не с проектом. Он выбирает его
последнюю стабильную версию, объединяет группы зависимостей всех целевых
платформ и повторяет это для каждого дочернего пакета. Поэтому набор вершин
может быть шире, а версии могут отличаться от результата восстановления
конкретного проекта. Это осознанное расхождение: вариант не содержит параметров
версии пакета и целевой платформы.
